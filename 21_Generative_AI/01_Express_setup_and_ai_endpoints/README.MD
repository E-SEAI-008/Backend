# AI API Basics – Token Usage & Insomnia Tests

### What are tokens, and why do they matter?

AI models process **tokens**, not just whole words. A token can be part of a word, a whole word, punctuation, or another piece of text. **One token is not necessarily one word.**

In a typical Chat Completions response:

| Field               | Meaning                                                                   |
| ------------------- | ------------------------------------------------------------------------- |
| `prompt_tokens`     | Input tokens: system instructions + messages and other request formatting |
| `completion_tokens` | Output tokens generated by the model                                      |
| `total_tokens`      | Input + output tokens                                                     |

**Why care?** Token usage affects **API cost** (input and output may have different prices) and how much conversation fits into the model's context window. Longer conversation histories generally require more input tokens.

---

### Insomnia setup – one request, no Express needed

Create a new request:

- **Method:** `POST`
- **URL:** `https://api.openai.com/v1/chat/completions`
- **Auth:** Bearer Token → paste your own OpenAI API key
- **Header:** `Content-Type: application/json`
- **Body:** JSON

**Never share or commit your API key.** An API key also requires a working API account with available usage/billing.

### Test I – single question (non-streaming)

Send this JSON body:

```json
{
  "model": "gpt-4o-mini",
  "messages": [
    {
      "role": "system",
      "content": "You are a helpful assistant. Keep your answers short."
    },
    { "role": "user", "content": "What is the capital of Germany?" }
  ],
  "max_tokens": 100,
  "stream": false
}
```

---

### Test II – include conversation history (non-streaming)

Keep the same URL and authentication. Replace the body with:

```json
{
  "model": "gpt-4o-mini",
  "messages": [
    {
      "role": "system",
      "content": "You are a helpful assistant. Keep your answers short."
    },
    { "role": "user", "content": "What is the capital of Germany?" },
    { "role": "assistant", "content": "The capital of Germany is Berlin." },
    { "role": "user", "content": "And France?" }
  ],
  "max_tokens": 100,
  "stream": false
}
```

---

### Test III – streaming vs. non-streaming

**Non-streaming (`"stream": false`):** The API waits and returns **one complete JSON response**. The text is found at `choices[0].message.content`, and the response normally includes `usage`.

**Streaming (`"stream": true`):** The API sends **a sequence of Server-Sent Events (SSE)** as output becomes available. Instead of a single response body containing the entire answer, you'll receive chunks with `choices[0].delta.content`.

Try the same question with:

```json
{
  "model": "gpt-4o-mini",
  "messages": [
    {
      "role": "system",
      "content": "You are a helpful assistant. Keep your answers short."
    },
    { "role": "user", "content": "What is the capital of Germany?" }
  ],
  "max_tokens": 100,
  "stream": true
}
```

**Insomnia tip:** Depending on the client version, streamed events may appear in an event/stream view or as raw `data:` lines. That's expected. Compare what you see with `"stream": false`.

---

### Summary

- `messages` gives the model the current request and any previous turns we choose to include.
- `usage` helps us understand token consumption.
- `stream: false` → one complete JSON response.
- `stream: true` → incremental SSE events; response text comes through `delta`.
- Keep API keys on the **server side** when integrating the API into Express.

## Anthropic Claude

### OpenAI vs. Claude

Both APIs use messages, roles, tokens and streaming. However, their request and response formats are different.

| Feature            | OpenAI Chat Completions       | Claude Messages API     |
| ------------------ | ----------------------------- | ----------------------- |
| Endpoint           | `/v1/chat/completions`        | `/v1/messages`          |
| Authentication     | Bearer Token                  | `x-api-key`             |
| System prompt      | Inside `messages`             | Separate `system` field |
| Conversation roles | `system`, `user`, `assistant` | `user`, `assistant`     |
| Output limit       | `max_tokens`                  | `max_tokens` (required) |
| Response text      | `choices[0].message.content`  | `content[0].text`       |
| Input tokens       | `usage.prompt_tokens`         | `usage.input_tokens`    |
| Output tokens      | `usage.completion_tokens`     | `usage.output_tokens`   |

### Insomnia Setup

Create a new HTTP request:

- **Method:** `POST`
- **URL:** `https://api.anthropic.com/v1/messages`
- **Auth:** No Auth (we will use headers)
- **Headers:**

[List of Claude Models:](https://platform.claude.com/docs/en/models/overview)

```text
x-api-key: YOUR_ANTHROPIC_API_KEY
anthropic-version: 2023-06-01
Content-Type: application/json
```

Never share or commit your API key.

### Test I – Single Question

**Body → JSON:**

```json
{
  "model": "claude-sonnet-5-5",
  "max_tokens": 100,
  "system": "You are a helpful assistant. Keep your answers short.",
```
